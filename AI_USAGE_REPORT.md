# Mandatory AI Usage Report

AI TOOL USED: Gemini

WHAT I ASKED AI TO DO:
1. Generate boilerplate SQLAlchemy 2.0 ORM models enforcing strict integer-based monetary types (paise) to prevent floating-point arithmetic degradation.
2. Design an append-only ledger service layer and a centralized state machine for payment transitions to guarantee financial immutability.
3. Formulate a comprehensive Pytest suite targeting boundary conditions, idempotency failures, state-transition violations, and Role-Based Access Control (RBAC) edge cases.

PROMPT THAT WAS MOST USEFUL:
"Act as a senior backend engineer. Scaffold the core ledger service and outstanding balance calculator. Strict constraint: The ledger must be strictly append-only (no UPDATE/DELETE exposed at the ORM or API layer), and the outstanding balance must be dynamically derived via SQL aggregations rather than maintained as a mutable column state."

CODE GENERATED BY AI: What part?
Initial architectural drafts for the SQLAlchemy ORM schema (`app/models.py`), the append-only ledger abstraction (`app/services/ledger.py`), the deterministic payment transition state machine (`app/services/payments.py`), Jinja2/HTMX UI templates, and foundational Pytest assertions (`tests/test_core.py`).

CODE I MODIFIED: What part?
Refactored `requirements.txt` to mitigate dependency resolution conflicts in Python 3.14. Manually resolved namespace isolation issues by explicitly exporting `MismatchType` in `app/models.py` and implementing the dependency injection callables (e.g., `get_current_user_role`) in `app/deps.py` after modularizing the codebase.

AI OUTPUT THAT WAS WRONG:
The AI initially recommended strictly pinned dependency versions (e.g., SQLAlchemy 2.0.28, Pydantic 2.6.4). Under Python 3.14, this forced `pip` to attempt compiling `pydantic-core` from source via Rust/Cargo, which failed locally due to missing MSVC build tools. Furthermore, SQLAlchemy 2.0.28 crashed on Python 3.14 due to changes in how `TypingOnly` base classes operate. Additionally, during the module splitting phase, the AI hallucinated imports by temporarily omitting the definition of the `MismatchType` enum and the auth dependency functions.

HOW I IDENTIFIED THE PROBLEM:
1. Build failures during environment provisioning: `linker link.exe not found... maturin failed`.
2. Runtime exception during Uvicorn startup: `AssertionError: Class directly inherits TypingOnly...` originating from SQLAlchemy's core operations.
3. Test suite collection failures: `ImportError` explicitly flagging missing schemas and dependency injectables.

HOW I FIXED IT:
I unpinned the strict versioning in `requirements.txt` to allow `pip` to resolve the latest pre-compiled wheels and bug fixes compatible with the Python 3.14 ABI. I also manually bridged the broken import namespaces by authoring the missing Enum models and FastAPI dependency definitions into their respective modules, ensuring the test suite achieved 100% passing status.
